# 獨立外部驗證集（External Validation Set）建置計畫

## 為什麼這份文件沒有直接附上 300～500 筆驗證資料

審查意見中最值得補的一項，是建立一組「不曾出現在 `data.csv`、
`feedback.csv`、template、fixtures，也沒參與過 tuning」的獨立 Benign／
Scam 驗證集。**這份文件刻意不直接附上捏造或未經查證的網址清單**，
原因是：

1. 驗證集的核心價值在於「標籤必須是真的」。若由 AI 在沒有即時瀏覽器、
   沒有查核機制的情況下批次生成幾百筆網址與標籤，品質完全無法保證，
   混進論文反而是更嚴重的研究誠信風險——這正是這次審查意見開頭強調
   「資料可信度」的精神，不應該用另一批來源可疑的資料去解決。
2. 「詐騙網址」清單本身若公開發布／寫入 git 歷史，可能被當成現成的
   釣魚網址導覽清單濫用，也不符合負責任揭露（responsible disclosure）
   的精神。
3. 時效性：詐騙網址壽命通常很短（數天到數週），此時此刻查證過的名單，
   一兩個月後可能已經失效、下架或轉手，驗證集需要「蒐集當下」就查證，
   而不是先列好清單再事後查證。

因此，本文件提供的是**方法論、資料來源建議、查核流程、與一支可直接
執行的蒐集腳本骨架**，由專題團隊實際執行、查核、簽名負責，而不是
代為生成一份品質無法保證的假資料。

## 建議的資料來源

### Benign（正常）樣本來源
- Tranco List（學術界常用的「熱門網域排行」，比 Alexa 更抗刷榜，
  `https://tranco-list.eu/`）取前 N 名中隨機抽樣，人工確認仍在正常
  營運（不是被接管的過期域名）。
- 台灣本地化來源：政府機關 `.gov.tw`、公立學校 `.edu.tw`、上市櫃公司
  官網（可對照公開資訊觀測站 `mops.twse.com.tw` 的公司清單）。
- 刻意納入「URL 結構複雜但合法」的案例（對照 `docs/ERROR_ANALYSIS.md`
  發現的誤判模式），例如知名品牌的多語系／帶追蹤參數網址，讓驗證集
  能真正檢驗模型在這類案例上的表現，而不是只放「乾淨網址」讓分數
  好看。

### Scam（詐騙）樣本來源
- 台灣「165 全民防詐騙網」公開揭露的詐騙網站清單（需人工確認仍為
  其公告內容，非第三方轉載）。
- PhishTank（`https://phishtank.org/`）、OpenPhish 等國際釣魚網址
  回報平台的近期（蒐集當下一週內）、已由社群驗證（verified）的項目。
- 與既有 `data.csv` 的 `scam_*` 類別做網域去重比對，確保沒有重複
  （即便是「同網域不同路徑」也應視為重複，避免資料洩漏）。

## 查核流程（人工，不可省略）

```
候選網址
  ↓
比對是否已出現在 data.csv / feedback.csv / 任何 train_model.py 使用的
template 或 fixture（exact URL 與 registered domain 兩個層級都要查）
  ↓
人工開啟（建議在隔離環境／虛擬機，不要用日常使用的瀏覽器）確認內容
  ↓
記錄查核時間、查核人、佐證來源連結（例如 165 公告頁、Tranco 排名截圖）
  ↓
標註 label，寫入 external_validation.csv（不納入訓練，只用於評估）
```

## 蒐集與查重腳本骨架

專案已提供 `scripts/build_external_validation.py`（見同目錄），功能：

1. 讀入候選網址清單（人工準備，CSV 格式：`url,label,source,checked_by,checked_at`）；
2. 自動比對 `data.csv`、`feedback.csv`、`train_model.py` 內建的
   template 網域清單，標示重複項目供人工複查；
3. 輸出去重後的 `external_validation.csv`，供 `train_model.py` 的
   `--benign-validation` / `TRUTHMARK_BENIGN_VALIDATION`（見
   `prior_selection` 欄位的說明）或獨立的評估腳本使用。

## 完成後如何使用這組資料

1. **絕對不要**把 `external_validation.csv` 併入 `data.csv` 重新訓練——
   它的價值就在於「模型從未看過」。
2. 用 `scam_model.pkl` 直接對這組資料跑預測（不訓練），計算
   Precision／Recall／F1／FPR，與 OOF 的數字並列比較，寫成論文新增的
   一張表：「OOF（資料集內泛化） vs External Validation（真正未知
   資料）」。
3. 若兩組數字差距很大，正是論文「系統限制」章節最誠實也最有價值的
   發現——比兩組數字很接近更值得討論（代表訓練資料的代表性、或是
   合成資料 `variant_ad`／`variant_flip` 等生成規則與真實世界有落差）。

## 建議規模與時程（口試前仍來得及的版本）

若時間有限，不需要一次做到 300～500 筆：

- **最小可行版本**：Benign 50 筆＋Scam 50 筆，當作「初步外部驗證」，
  論文中誠實標註樣本數有限、未來可擴大規模，依然比完全沒有獨立驗證集
  更有說服力。
- 時程建議：查核流程本身最花時間的是「人工逐筆確認」，50＋50 筆以
  兼職方式（每天查核 20～30 筆）約 3～4 天可完成。
