# 風險門檻選擇說明：0.05 / 0.40 / 0.70

這份文件說明為何模型在 OOF 評估中以數學指標搜尋出的最佳門檻，與系統產品實際採用的風險門檻不同。
以下數字均以目前 `model_report.json → oof_metrics` 為準。

## 三個數字分別是什麼

| 門檻 | 來源 | 意義 |
|---|---|---|
| **0.05** | `best_f2_threshold` | 純模型指標最佳解；OOF 上 F2 = **0.8892**、Precision = **0.6671**、Recall = **0.9699**。 |
| **0.40** | 系統程式碼實際使用的中風險門檻 | 產品決策門檻；OOF Precision = **0.9284**、Recall = **0.7028**、FPR = **4.89%**。 |
| **0.70** | 系統程式碼實際使用的高風險門檻 | 高置信度警示門檻；OOF Precision = **0.9928**、Recall = **0.5502**、FPR = **0.36%**。 |

## 為什麼不直接用數學最佳的 0.05

若把 0.05 直接當成正式產品門檻，雖然 Recall 達到 0.9699，但 Precision 只有 0.6671；
換言之，被標示為有風險的網址中，約三分之一並非詐騙。對瀏覽器擴充套件而言，過高的誤報可能造成
警示疲勞並降低使用者信任，因此模型數學指標的最佳切點不一定等於產品最佳決策門檻。

## 為什麼採用 0.40

本研究將 0.40 作為產品中的中風險門檻，主要考量：

1. **系統定位是風險預警，而非唯一防線。** 白名單、黑名單與硬規則已處理部分明確案例，AI 模型
   主要處理灰色地帶，因此不以單一模型門檻承擔全部防護責任。
2. **控制誤報。** 0.40 的 OOF FPR 為 **4.89%**，比追求高 Recall 的低門檻更適合作為日常瀏覽情境的
   使用者警示分界。
3. **保留第二級高風險門檻。** 0.70 的 Precision 達 **0.9928**、FPR 僅 **0.36%**，可用於更強烈的
   高風險視覺警示或攔截情境。

## 校準與目標風險比例

目前校準採用 `target_prior = 0.2`。`model_report.json` 同時記錄：

- Brier（目前 OOF 校準結果）= **0.1263**
- Brier（未校準）= **0.1039**
- 以目標 prior 校準的 Brier = **0.0682**
- 以目標 prior 校準的未校準 Brier = **0.0767**
- 目前未提供獨立 benign 驗證集，因此 `target_prior = 0.2` 為**假設值**，不應解讀為正式部署流量的實測比例。

## 建議寫進論文的段落

> 模型在 OOF 驗證上以 F2 指標搜尋出的數學最佳門檻為 0.05（F2=0.8892，Precision=0.6671，
> Recall=0.9699），然而若直接採用該門檻作為產品決策依據，將造成較高的誤報。因此，本系統改以
> 0.40 作為中風險門檻（Precision=0.9284、Recall=0.7028、FPR=4.89%），並以 0.70 作為高風險門檻
> （Precision=0.9928、Recall=0.5502、FPR=0.36%），在風險預警與使用者體驗之間取得較適當的平衡。
> 此外，目前校準所使用的 20% target prior 為假設值，仍需透過獨立外部驗證資料進一步估計與確認。
